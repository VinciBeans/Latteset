# 用户文案规范（copy-guide）

> **这是什么**：Latteset **用户可见文案**的写作与检查规范（界面标签、按钮、空态、对话框、错误/提示、状态词）。
> **事实来源**：术语含义以 [glossary.md](../glossary.md) 为唯一源；本文件只规定**界面怎么说**，不得改写术语表的含义。实现契约（状态怎么来、确认怎么做）见 [modules.md](./modules.md) §2.6.1/§2.7/§9/§10；验收入口见 [testing.md](./testing.md)「真机验收」与「文案一致性（T35–T42）」。
> **来源与基线**：外部文案审查报告（2026-11-21，60 条）+ T34 分诊 + T35/T36/T37 落地 + T40/T41 复核 + T38 真机抽验。报告建议的短名（内置精简集 / 在线完整集 / 本地文件夹）**已由 lead 裁定不采纳**（与 glossary 冲突），三档统一用 glossary 全名。
> **纪律**：只写已验证事实；未实测的检查项标 `[未测]`。

## 1. 八条硬规则

### 1. 状态要说下一步动作

一个状态不是终点：要么说清「正在发生什么」，要么给出「现在能做什么」。状态机黑话（未确定 / 覆盖未更新 / 已诊断）不进界面。

- 正例（已落地）：`尚未指定根文件 · 点击选择`（状态 + 下一步）；文件树空态 `还没打开项目 / 点顶部「打开项目」开始`；缺包诊断给三条可执行出路。
- 状态词本身允许（`未编译` / `就绪`），但页面必须同时有可执行入口（工具栏「编译」按钮、设置页链接等），不能只有一个状态词。
- 反例（已改掉）：`未确定根文件 · 点击选择`、`根文件覆盖未更新`、`已诊断 N`（后两者是实现状态，不是用户下一步）。
- **状态三态齐全**（报告 8 条之外的补充，已按 A-01/A-02 落地）：每个状态类信息至少覆盖 未开始 / 进行中 / 已完成——问题面板 = `还没有编译`（灰圈，未编译）/ `排版中…`（进行中）/ `没有发现问题`（绿勾，完成）/ 失败时给条目；状态栏 = `未编译` / `排队中…`、`排版中…` / `就绪`、`失败· …`。缺「未开始」文案即 bug（A-01/A-02 的根因）。

### 2. 一个动作一个主按钮

一个区域 / 一个对话框只有一个主按钮（primary），其余是次要或取消；同一动作不要用两个不同名字。

- 正例（已落地）：设置面板 footer 主按钮 = `关闭`（`应用` 只出现在需要显式提交的输入行）；新建向导 footer 只留 `取消 / 创建`（说明文字删掉）；确认框 = `取消 / <动作名>`（`采用磁盘版本`、`恢复默认`、`丢弃并继续`）。
- 反例（已改掉）：footer 的 `完成` 实际只是关闭；向导 footer 塞设问+说明书。

### 3. 否定说替代动作

不要只写「不会 / 不支持」；把用户能走的路写出来。纯否定的内部承诺（「不会静默降级」）不进用户界面。

- 正例（已落地）：缺包诊断给三条出路（切 `在线完整宏包集` / 补 `本地目录宏包集` / 改 `\usepackage`）；内置集缺失给 `重新安装` 与 `显式切换`；关于页删掉「不会静默降级」半句。
- 保留的例外（durable keep）：失败现场保留一句「**不会自动切换到在线宏包集，需要你在设置里显式选择**」——它是用户判断"要不要等/换源"的唯一依据（ADR-0016 决策 2），属"说清替代动作"的否定句，不是空泛保证。

### 4. 单位用中文（数字与单位间留空格）

- 正例（已落地）：`900 秒`、`1800 秒`、`500 毫秒`、`120 秒`（超时/防抖提示）。
- 反例（已改掉）：`900s`、`1800s`、`500ms`。
- 例外：状态栏行列号保留 `Ln 12, Col 5`（编辑器惯例，T25 判 keep，见 [glossary.md](../glossary.md)「行列号」）；`PDF` / `SyncTeX` / `tmp/` 等技术名不翻译。

### 5. 无主语或明确系统主语

优先祈使句（无主语）；必须自述时主语用产品名 `Latteset`，不要用「我们 / 本产品 / 本应用 / 本引擎」。

- 正例（已落地）：`Latteset 没有回收站`；`点顶部「打开项目」开始`。
- 反例（已改掉）：`我们…`、`本产品把中间文件统一收纳在 tmp/`、`本引擎不会自动运行它`。
- 引擎表述：概念名用 [glossary.md](../glossary.md) 的**内嵌引擎**；界面出现引擎名时写 `内嵌 Tectonic`（引擎名 + 唯一形态），不得写「库形态 / 子进程档 / 两形态 / 引擎可选」。

### 6. `title` 只作补充

承重信息（后果、出路、状态含义）必须在可见文本里；`title` / `aria-label` 只补充说明或给可访问名。键盘/触屏用户拿不到 `title`。

- 正例（已落地）：编译模式 chip 的 `title` = `当前：连续编译（点击查看其它编译模式）`，两个模式的含义**在菜单里可见**（`编辑停顿后自动编译（防抖时长在设置里）` / `点「编译」或保存文件时编译`）；运行时提示 chip 的 `title` 末尾 `（点击展开全文）`，正文点开可见。
- 反例（已改掉）：长诊断只放 `title`、正文单行截断；把唯一出路写进 `title`。
- 现状基线（T38，2026-11-21）：`title=` **52 处**（静态 33 + `:title` 19）、`aria-label` **15 处**、`aria-labelledby` 4 处——**全仓 title 规则的系统性整改（C-01 后续批）`[未测]`/未做**，本规范对新增文案生效。

### 7. 不可逆动作必须确认

会覆盖/删除/不可撤销的动作，点击后必须先弹确认，且确认框写清「动什么 + 后果 + 能不能撤销」；确认按钮写**动作本身**，不写「确定」。

- 正例（已落地）：
  - 外部修改 chip → `采用磁盘上的版本？`，正文「采用磁盘版本会覆盖你未保存的修改，且无法撤销。」，按钮 `取消 / 采用磁盘版本`；
  - 设置页 `恢复编译项默认` → 确认框列出将重置项（编译模式 / 防抖 / 超时 / 新建文件向导），并声明根文件覆盖与引擎资源不受影响；
  - 有未应用输入时切页 / 关闭 → `有未应用的输入` + `取消 / 丢弃并继续`；
  - 删除文件沿用 `ConfirmDialog`（项目没有回收站，不可撤销）。
- 反例（已改掉）：外部修改 chip 单击直接覆盖本地缓冲；`恢复默认` 无确认、承诺范围大于实际作用范围。

### 8. chip 不做「单击即覆盖 / 即清除」

破坏性动作的 chip：单击只打开确认，不直接执行；提示类 chip：单击是**展开/查看**，不是销毁。

- 正例（已落地）：外部修改 chip 单击 → 确认框（取消后冲突标记与本地内容都保留）；运行时提示 chip 单击 → 展开全文 + 展开「问题」面板，**不销毁**，再点收起；`aria-expanded` 同步。
- 例外：设置里的**持久提示**（`Settings.notices`）点击 = 「不再提示」并写盘，这是显式 dismiss 语义；其文案必须让用户预期"点掉就不再出现"。
- 反例（已改掉）：运行时提示 chip 单击即 `notices.clear()`；外部修改 chip 单击即读盘覆盖。

## 2. 术语表（概念 / 唯一说法 / 禁止说法）

| 概念 | 唯一说法（界面） | 禁止说法 / 备注 |
|---|---|---|
| 产品名 | `Latteset` | TeXPresso / TeXEditerB（旧名/占位名） |
| 编译入口文件 | **根文件**；首次出现给一句白话：「编译的出发文件（含 `\documentclass` 的顶层 .tex）」 | 主文件 / 入口文件 / 主 tex / 未确定根文件 |
| 引擎与形态 | 概念 = **内嵌引擎**；界面写 `内嵌 Tectonic` | 库形态 / 子进程档 / 两形态 / 引擎可选 / 本引擎 |
| 宏包集 | **宏包集**（首次出现括注 `（bundle）`） | bundle（裸用）/ bundle 源 / 精简集（单独作全名）/ 宏包缓存 |
| 三档来源之一 | **内置精简宏包集**（短名仅在空间不足处：`内置精简`） | 内置（默认）/ 内置精简集 / 内置宏包集 / 随包精简集 |
| 三档来源之二 | **在线完整宏包集**（短名：`在线完整`） | 在线完整 / 在线集 / 完整集 / 在线完整包 |
| 三档来源之三 | **本地目录宏包集**（短名：`本地目录`） | 本地文件夹 / 本地目录 / 本地 bundle / 本地集 |
| 底部问题区 | **问题** / **问题面板**；计数 `N 个问题`（折叠头）| 报告 / 错误列表 / 诊断面板 / 「已诊断 N」 |
| 编译未开始 | **未编译**（无项目时不渲染状态 chip） | 空闲 / idle / 初始态 / 未开始（"未开始"只作设计口径，不直接入界面） |
| 编译进行中 | **排队中…**（queued）/ **排版中…**（running） | 编译中（笼统）/ 正在排版（与 running 混用） |
| 编译完成 | **就绪**（至少成功编译过一次且当前不运行）；失败显示 **失败· 内容错误 / 失败· 超时** | 编译成功（那是事件结果）/ 已编译 / 空闲 |
| 草稿强度提示 | **引用待更新**（chip）；「草稿」是强度概念（草稿编译），不单独当状态词 | 编译中预览（那是预览能力）/ 草稿编译当状态词 |
| 起步文档 | **起步文档** | 骨架 |
| 编译模式 | **连续编译** / **保存时编译** | 保存触发（界面）/ 自动编译 / 实时模式 |
| 缓存位置 | **缓存目录** / `程序缓存目录（默认）` | 应用缓存目录 / cache 目录 |
| 时间单位 | `900 秒` / `500 毫秒`（数字与单位间空格） | 900s / 1800s / 500ms |
| 行列号 | `Ln 12, Col 5`（状态栏；T25 判 keep） | 第 12 行第 5 列（正文叙述可以，状态栏不换成中文，避免宽度抖动） |

**一致性约束**：

1. 三档宏包集**全名**必须与 [glossary.md](../glossary.md) 逐字一致：`内置精简宏包集` / `在线完整宏包集` / `本地目录宏包集`；首现处可括注 `（bundle）`，但不得用报告建议的短名当正式名。
2. 「内嵌引擎」「根文件」的**含义**以 glossary 为准，本表只约束界面写法；要改含义先改 glossary（事实源），再同步此处与界面。
3. 同一视图内不得混用全名与短名；短名只在空间实在不够处（如窄按钮）使用。

## 3. 检查方法（可见串 grep 清单）

> 口径 = T25/T38 的「可见串」：`src/**` 的 `<template>` 文本、`title`/`aria-label` 等属性、用户可读字符串常量。**注释 / 文档注释 / 日志 / 测试 / `src/bindings.ts` 生成物不计**（T38 实测：13 个内部词原始命中全部落在注释/测试/doc 注释，可见串 0）。

```powershell
# ① 内部词/旧说法：先全量命中，再逐条判定是否落在可见串（注释白名单）
$src = Get-ChildItem src -Recurse -File -Include *.vue,*.ts |
  Where-Object { $_.FullName -notmatch '__tests__|bindings\.ts' }
$tokens = 'bundle 源|精简集|内置宏包集|本地 bundle|报告|错误列表|诊断面板|已诊断|骨架|命中|模糊匹配|Candy Desk|驱动形态|本产品|本应用|本引擎|我们|不会静默降级|未确定根文件'
$src | Select-String -Pattern $tokens -Context 1,0

# ② 时间单位：中文单位 + 空格
$src | Select-String -Pattern '\b(\d{2,4})\s*(s|ms|sec|milliseconds?)\b'

# ③ title / aria 口径（只统计，不自动判违规；承重信息必须在可见文本）
$src | Select-String -Pattern '(\s|:)title=|aria-label|aria-labelledby' | Measure-Object
$src | Select-String -Pattern '(\s|:)title=' | Measure-Object

# ④ 后端用户面文案（同一批禁用词；Rust 注释同样白名单）
Get-ChildItem crates -Recurse -File -Include *.rs |
  Where-Object { $_.FullName -notmatch 'tests|target' } |
  Select-String -Pattern '本产品|本应用|本引擎|我们|不会静默降级|下方按钮|tmp/|驱动形态'
```

**判定流程**：

1. 每条命中先看是否**用户可见**（模板文本/属性/字符串常量）；注释、测试、日志 → 白名单放过。
2. 命中即改：优先补替代动作（规则 3）或换成 glossary 唯一说法（§2），不改含义、不改行为。
3. 改文案后同步断言：`npm run test`（vitest 18 files / 189 tests 是 T41 基线）；测试选择器优先 `data-testid`，**不要用可见文案当语义标识**（文案可以改，语义标识不能跟着漂）。
4. 门禁 + 抽验：`npm run build`、`npm run test`、`npm run lib:test`（399 passed / 8 ignored）、bindings 13/13；涉及交互/主题/状态时按 [testing.md](./testing.md)「真机验收」新增条目抽验（确认框 / 未编译态 / 深色 token / 窗口标题）。
5. 基线数字只作对照（T38，2026-11-21）：可见串内部词 **0 命中**；`title` 52、`aria-label` 15、`aria-labelledby` 4；全仓 title 系统性整改（C-01）与图标体系（C-04）、面板高度（C-11）、设置入口收敛（C-13）属**后续批**，未完成、`[未测-后续项]`。
