# 片段预览：只编译「导言区 + 改动那一段」（草稿层真实排版实验 (A)，2026-09-16）

> **一句话**：把编辑中的那一段，连同项目自己的导言区装成一份**独立小文档**单独编译，用真实排版
> 给出一张片段卡。它**不是**"文档里那一页"（页号/浮动体/上下文都不同），而是"这段文字排出来什么样"。
>
> **状态**：已落地并真机验证（`compile_snippet` 命令 + `SnippetPreview.vue`），**整块可回滚**。
> **待产品判断**：与现有草稿层（字符近似，31–34 ms）相比是否更好用 —— 这正是本轮要收集的"落地效果"。

## 1. 与另外两条路的关系（先看清边界）

| 方案 | 产出 | 实测成本（125 页/462 KB 夹具，release） | 保真度 |
|---|---|---|---|
| 现有**草稿层**（先做且仍在） | 改动那一行，系统字体近似 | **31–34 ms**（纯前端） | 只画一行、不重排 |
| **(A) 片段预览**（本文，已落地） | 改动那一段，**真实排版** | **~200 ms**（见 §3） | 文字/公式/断行真；**页号与位置无关** |
| (B) 截断编译（未做） | 文档前 N 页 | 65 ms + 13.2 ms/页 | **与全篇逐页字节一致**（对拍 35 页） |
| (C) `\includeonly`（未做） | 该章的页范围 | 导言区 + 该章 | 编号正确；要求 `\include` 结构 |

**TeX 是顺序处理器**：页断依赖全部前文，所以"只从片段开始排"得到的不是文档里的那一页。(A) 的价值
不在位置保真，而在**极快拿到真排版**（公式、宏、断行都对）。

## 2. 实现形状（为什么这样切）

- **后端**：`compile_snippet(snippet)` 命令。把根文件 `\begin{document}` **之前**的内容逐字作为导言区，
  与片段拼成 `main.tex`，写到**独立项目根** `<项目>/tmp/snippet/`，用**与主编译同一个 runner**
  （`SwitchableRunner`，形态/引擎/包设置完全一致）编译，返回 `{path, elapsed_ms}`。
  - **独立项目根**是关键①：产物落 `tmp/snippet/main.pdf`、中间产物落 `tmp/snippet/tmp/`
    ⇒ **不碰权威 `<stem>.pdf`、不碰主编译的 `tmp/`**。上一轮实测过踩坑：草稿编译会把权威 PDF 覆盖掉。
  - **每次清空重建**：片段之间不共享 aux（否则上一段的 `\label` 会串到这一段）。
  - `tmp/` 在监视器与文件树的忽略清单里 ⇒ 不会反过来触发编译（实测日志确认：`tmp/snippet/*` 全部"忽略路径"）。
  - **不经调度器**：调度器完成时会发 `compile-status`/`pdf-updated`，中间产物一旦冒充权威产物，
    页哈希基线、A 闸门与「引用待更新」语义都会被污染。进度出口换成 no-op（片段的页数/错误不进状态栏与错误列表）。
- **前端**：`SnippetPreview.vue` 悬浮卡。改动 → 350 ms 去抖 → 取**改动行所在的段落**（`services/snippetPatch.ts`，
  纯函数、有单测）→ 调命令 → pdf.js 渲染第 1 页 → **按文字包围盒裁剪**后画进卡片。
  - **契约两条**（组件自己守）：① `phase === "running"` 时**不调**（引擎是**进程内**全局锁，会把主编译顶住）；
    ② 结果**只用于看一眼**（不写当前文档 / 页哈希 / A 闸门）。
  - 卡片 5 秒后自动收起；权威 `pdf-updated` 到达也收起（真画面已就位）。
  - 失败**如实显示**（"无法单独编译：<首条错误>"）：宏定义在正文里、`\cite` 没有 aux 都是常见情形。

## 3. 实测

**成本**（release、库形态、125 页夹具；`format_ms=0` 热 format）：

| 量的是什么 | 读数 |
|---|---|
| 最小片段文档（导言区 + 1 行） | 第 1 趟 **79 ms** |
| **本夹具的真实片段文档**（3 次） | 墙钟 **204 / 200 / 198 ms**（`typeset=151–161`、转换 1 ms、1 趟） |
| 同一台机器上全篇 125 页 | 第 1 趟 1716 ms（完整收敛 7.4 s） |

⇒ 片段预览把"真排版"从 ~1.7 s 压到 **~0.2 s**（约 1/8），而它要处理的正是用户此刻在改的那一段。

**dev（debug）构建下同一操作 ~2.7–2.9 s**：debug 的转换阶段被放大 ~12×，**不能用手感评估 dev 数字**。

**真机（GUI 库形态）**：卡片显示真实排版（`\textbf` 粗体、`$E=mc^2$` 斜体、按正文行宽断行），
头部 `2536 ms · 真实排版`（debug），文字包围盒裁剪后画布 `336×35`。

## 4. 真机验证抓到并修掉的三个 bug（单测抓不到）

1. **`\graphicspath` 注入位置错**：它在 `\documentclass` 之前还没定义（`graphicx` 提供的）
   ⇒ 片段文档直接 `! Undefined control sequence`。改成"`\input@path` 在最前 + `\graphicspath` 在
   `\begin{document}` 之后且用 `\@ifundefined` 守卫"。
2. **页脚页码撑高裁剪框**：片段卡按文字包围盒裁图，而 `getTextContent()` 含页脚页码 ⇒ 两行片段被裁成
   `336×560`、正文挤在顶部一条。修：片段文档 `\pagestyle{empty}`。
3. **画布尚未挂载就渲染**：canvas 在 `v-if` 里，`visible = true` 之前 `canvasRef` 是 null ⇒ 静默 return
   留下一张空白卡。修：先显示 → `nextTick()` → 再渲染；并且"画布缺失"改为**显式抛错**（静默失败正是它藏了一轮的原因）。

另记：MCP 的合成按键**驱动不了 Monaco**（`press`/`type` 都被忽略，也没有 EditContext）⇒ 真机验收走
`window.__snippetPreview`（与 `window.__previewLastReload` 同款的外部可观测约定）：它只走"编译片段 → 渲染卡片"
这条流水线，不改缓冲、不写文件。

## 5. 明确的边界（别当成"那一页"）

- **版式无关**：片段从第 1 页第 1 行开始排，页号、浮动体位置、`\parindent` 之外的上下文都与真文档不同；
- **只有导言区里的宏**：正文里定义的宏、`\input` 进来的正文内容不可用；
- **没有 aux**：`\cite`/`\ref` 会得到 `??`（与草稿态同性质）；
- **中文字体取决于项目导言区**：夹具是 `article`（无 CJK 支持）⇒ 中文片段排成缺字（**这是忠实结果**，
  不是管线故障；换 ctex/`xeCJK` 的工程就正常）；
- **与主编译互斥**：编译中直接跳过（进程内全局锁）；那段窗口由草稿层兜着。

## 6. 回滚与后续

- **回滚**：删 `src/components/SnippetPreview.vue` + `App.vue` 里的一行挂载 + `commands.rs` 的
  `compile_snippet`（含 specta 注册）与 `ipc.ts` 一行 + core 的 `snippet.rs`；不触碰预览面板的渲染契约。
- **评估要点**（产品判断）：~0.2 s 的真排版片段（release）是否比 31–34 ms 的字符近似更有用？
  是否该常驻（而不是自动收起）？是否该接到**悬浮在光标附近**而不是右下角固定？
- **若要更接近"那一页"**：走 (B) 截断编译（成本随位置 0.2–1.4 s，前缀与全篇逐页一致），
  截断页可由 SyncTeX 正向定位（改动行 → 页号）算出；但那需要另起进程才能与主编译并发。
