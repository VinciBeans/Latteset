## §1 机制：`bop` 布局与「被打脏页数 = N − m − 1」

### 1.1 字节布局（实测：`[t4] §4`、`[E] v1v2-detail.txt`）

DVI/XDV 每页以 45 B 的 `bop`（opcode `0x8B` = 139）开头：

| 页内相对偏移 | 长度 | 内容 |
|---|---|---|
| `0` | 1 B | opcode `139` |
| `1..41` | 40 B | `c0..c9`，各 big-endian i32（TeX 的 `\count0..\count9`；`c0` 是 LaTeX 页计数器） |
| **`41..45`** | **4 B** | **`prev`，i32 = 上一页 `bop` 的绝对字节偏移**（页 1 = `-1`） |

* 页切片（产品口径）= `bytes[bop ..= eop]`；`xdv.rs:176-212` 的解析循环里 `p` **恰好越过 EOP 字节**（`xdv.rs:196-199` 的 `p += 1`），所以 `xdv.rs:211` 哈希的就是「45 B 头 + 正文 + 1 B EOP」。
* 实测边界：`thesis` / `multifile` 两夹具 `preLen = 44` ⇒ 页 1 的 `bop = 44`、页 2 的 `prev = 44 = B₁`（`[t4] §4`、`[D] <夹具>/_baseline/hashes.json`）。
* 反证替代读法：把 `prev` 读在页内偏移 `1..4`（另一种可能的字段顺序）在 **4284 页次里 0 命中** ⇒ `41..44` 是唯一正确读法（`[t4] §4`）。

### 1.2 公式及其推导（`[t1] §2.5`）

设第 i 页切片长 `L_i = 45 + body_i + 1`、`B_i = B_1 + Σ_{j<i} L_j`（+页间填充）、`prev_i = B_{i-1}`。
一次编辑若使**最早发生长度变化**的页为 `m`（变化量 ≠ 0，且其后没有别的长度变化）：

```text
C_raw = {m} ∪ {m+2, m+3, …, N}
         ↑ 真变化   ↑ 假阳性：这些页的 prev = B_{j-1} 整体平移，页体逐字节未变
         （第 m+1 页的 prev 仍指向 B_m，未动 ⇒ 逐字节相同）
口径变化页数 |C_raw| = N − m        ← 固定名词 1（含真变化页）
假阳性页数            = N − m − 1    ← 固定名词 2（不含真变化页；例：N=28、m=4 ⇒ 24 / 23）
```

`m = N`（改末页）⇒ 假阳性 0，公式自然退化。

### 1.3 验证（`[q].formula`、`[t2表]` 的「公式成立」列）

| 断言 | 成立 | 说明 |
|---|---|---|
| `C_raw == {m} ∪ {m+2..N}`（适用集 = c1/c2/c5 共 18 例） | **17/18 = 94.44%** | 全 42 例中「精确命中」18/42（多出的 1 例是 `multifile-last-c3` 的退化巧合） |
| 口径变化页数 `== N − m` / 假阳性页数 `== N − m − 1` | **17/18** | 同上集合；即 §3 的 FP 列 |
| 第 `m+1` 页逐字节相同 | **17/18** | 唯一不成立者即反例 |

* **唯一反例 `multifile-last-c5`**（k = 73、N = 74、Δsrc = +9 B）：`C_raw = {73,74}`、**渲染真值同为 `{73,74}`**。机制 = 第 73 页（倒数第二页）尾部追加 9 B **溢出到末页** ⇒ **第 73 与第 74 页都变长了**（t4 用字节最早变长页独立测得 `lenChg = [73,74]`），公式前提「单一长度变化页」被打破；**方向是"多报真变化"，不是漏判/误报**（`[t3] §8`、`[t4] §8.8`）。
* 同矩阵内对照：`multifile-last-c1`（+3 B）/`c2`（−3 B）不触发溢出（`C_raw = {73}`，成立）；`thesis-last-c5`（+9 B）也不溢出（`{25,27,28}`，成立）⇒ 反例取决于**该页剩余空间**，不是公式写错。
* **`m` 与 `k` 不是同一个量**：本文用 `k`（synctex 求得的编辑页）是因为矩阵是单点编辑；`k` 只是代理量——1/42 例（`multifile-first-c6`，改章标题，标题+目录联动）的 `k = 6` **不在** `C_raw = {7,8}` 内。用 `k` 反推机制时不要把它当「变化集合的最小页」（`[t3] §5` 附带发现、`[t4] §8.8`）。
* **页数变化分支**：`xdv.rs:223-232` 在「页数不同或基线缺失」时直接返回**全部页**为变化。t4 实测触发一次（删 `ch08`：N 28→25、`changed_pages` 全变化）⇒ 该分支**归一化零收益、也不会漏判**（`[t4] §2.5`）。本矩阵 42/42 例页数一致，未触发该分支（`[t3] §1`）。

## §2 口径定义：raw / V1 / V2 + 渲染真值

### 2.1 三种页哈希口径（可照抄的字节区间）

设某页 `bop = b`、`eop = e`（绝对偏移），页切片 `S = bytes[b..e+1]`：

| 口径 | 取哪些字节（页内相对偏移） | 长度 | 保留的东西 |
|---|---|---|---|
| **raw**（现实现，`xdv.rs:211`） | `[0 .. 45+body+1)` | `45+body+1` | opcode + 10×i32 计数 + i32 **prev** + 正文 + EOP |
| **V1**（推荐） | `[0 .. 41)` ++ `[45 .. 45+body+1)` | `41+body+1` | opcode + 10×i32 计数 + 正文 + EOP（**丢 4 B prev**） |
| **V2** | `[45 .. 45+body+1)` | `body+1` | 正文 + EOP（**丢整个 45 B 头**） |

```rust
// 现实现（xdv.rs:211）
out.push(hash_page(&bytes[bop..p]));

// V1：丢 4 B prev，保留 opcode + 10×i32 计数
let mut t = Vec::with_capacity(p - bop - 4);
t.extend_from_slice(&bytes[bop..bop + 41]);   // 0..41 = opcode + c0..c9
t.extend_from_slice(&bytes[bop + 45..p]);     // 45..   = 正文 + EOP
out.push(hash_page(&t));

// V2：丢整个 45 B bop 头
out.push(hash_page(&bytes[bop + 45..p]));
```

```js
// 工具路径（scripts/xdv-report.mjs 的 pagesDetail 提供 bopOffset/eopOffset）
const b = page.bopOffset, e = page.eopOffset;
const raw = sha(buf.subarray(b, e + 1));
const v1  = sha(Buffer.concat([buf.subarray(b, b + 41), buf.subarray(b + 45, e + 1)]));
const v2  = sha(buf.subarray(b + 45, e + 1));
```

* **V1 比 V2 保守**：V2 多丢 40 B 计数器（`c0` = LaTeX 页计数器、`c1..c9`）。真实语料确实有用 `\count1..\count9` 的类（普查**全局** 17 页 `c1..c9` 非零，其中 `trip.xdv` 的 16 页全占 —— **写「trip 16/16 页 `c1..c9` 非零」，不要写成"trip 的 16 页有 17 页"**，17 是普查全局计数，F4）。
* 本矩阵 **V1 与 V2 的变化页集合逐例完全相同**（`[q]`：`Σ|C_V1| = Σ|C_V2| = 40`）⇒ 矩阵分不出两者，本文推荐 V1 是**保守性**取舍，不是实测差异。
* ⚠️ `scripts/xdv-report.mjs` 输出里的 `hash` 字段是 **raw 的 sha1 前 16 位**，**不是 V1/V2**；Rust 用 `DefaultHasher`（SipHash-1-3，固定初始态、跨进程可复现，`[E] hasher-probe.txt`），Node 侧**无法复现哈希值** ⇒ 跨实现只能对拍「口径 / 边界 / 变化页集合」，不能对拍哈希值（`[t1] §5`）。

### 2.2 渲染真值（独立于三口径）

* **逐页 PNG SHA-256**：`pdftoppm -r 120 -png`，固定 dpi = 120（`[t2] §5`、`[D] hashes.json` 的 `baselinePngSha256[]` / `edit.pngSha256[]`）。
* 真值自稳性（t2 自测 + t4 **自跑复核**）：同一份 XDV、**同一固定输出路径**渲染两遍 ⇒ 逐页 PNG 哈希全等（28/28、74/74）；换输出目录仍逐页全等；t4 另测 72/120/150 dpi × `-aa no/yes` ⇒ **变化页集合不变**（`[t2] §5`、`[t4] §5`）。
* **PDF 字节不可作为比较判据**（方法学警示）：同一份 XDV 只换命令行的输出**路径字符串** ⇒ PDF 字节不同（thesis 72,800 vs 72,789 B；multifile 95,088 vs 95,089 B）、`/ID` 随名变；但逐页 PNG 哈希相同（`[t1] §2.3`、`[t2] §4.3`、`[t4] §5`）。本批全部结论只用「逐页文本 + 逐页位图」。
* 真值的**边界**：三口径都只看**页切片**，`pre`/`post` 段差异对三口径不可见（F3，见 §4.3）。

1. **锚点不是本轮实测**：102→7 ms 那次是「可见页全部未变（0 页重绘）」的测量，7 ms 含固定开销，**不能线性反推**每页成本；`9.14` 与 `14.57` 之间的 **1.6×** 就是真实不确定度。

4. **未计入**：二次渲染/缩放/滚动保持、Canvas/GPU 差异、CPU 竞争、PDF 变大对 `parse` 的影响。
5. 换算公式是**线性外推**（`FP × c`）；一旦真实实现改成"只重绘可见且失效的页"（当前 C 的语义），线性外推只在"误判页全可见"时成立。

## §6 风险与缓存迁移

### 6.1 现状（读码，`crates/latteset-infra/src/runner.rs`）

* 缓存路径 `tmp/<stem>.<引擎>.pages`（`runner.rs:199-211`；按引擎分文件是已知债 #25 的修法，Quick/Full **故意共享**同一份，见该处注释）。
* 格式：每页一行 `{h:016x}`（写：`runner.rs:572-580`）；读：`runner.rs:554-569` 逐行 `u64::from_str_radix(t, 16)`，**任一行解析失败 ⇒ 整个缓存当 `None`（fail-closed）**。
* 判据：`runner.rs:472-474` 的 `unchanged = !page_hashes.is_empty() && prev == page_hashes`；Quick 且 `unchanged` 且项目根已有 PDF ⇒ 跳过 `xdvipdfmx` 转换与拷贝（`runner.rs:477-491`），否则转换 + 拷贝 + 写缓存（`:511`）。
* 产品语义（`xdv.rs:216-233` 的文档注释 + 实现）：`prev` 为 `None` **或**与 `cur` 页数不同 ⇒ **全部页算变化**（含首次编译）；`cur` 为空（XDV 缺失/损坏）⇒ 返回**空表**，含义是"**无法判定**"，由调用方以 `pages == 0` 让前端全量刷新（**不要**把它与"零页变化"混淆）。

### 6.2 老缓存的风险方向（**保守**，可量化）

| 场景 | 量化代价 | 频率 |
|---|---|---|
| 老缓存（raw 行）被新代码（V1 比较）读到 | 首轮逐页皆不等 ⇒ A 面白跑 `xdvipdfmx` **0.65–0.94 s**（`docs/research/dvi-preview-feasibility.md` §3；`runner.rs:241` 记 0.65–0.94 s）；C 面视窗全量重绘 **64.0–102.0 ms**（**推算**） | 每个项目**一次性**；该轮写回新口径缓存即**自愈** |
| 新老二进制交替（灰度/回滚） | 每交替一轮再付一次同样代价 | 方案 A（文件名带口径）可降到 **0**；方案 B 仍是每交替一轮，但可解释、可人工核验 |
| 完全不迁移（只改哈希区间） | 与老缓存场景同量级，之后写回新格式；**回滚**时老二进制读新行再付一轮 | 无"永久零命中"风险 |
| 永久零命中（方案 A 的 token 漏写 / 方案 C "每次启动删缓存"） | A 面**每轮**白跑 0.65–0.94 s ≈ Quick 单趟编译中位 2081 ms 的 **31–45%** | **必须避免**；方案 A 需保证口径 token 只有一个落点 |

* 方向性：不等只会偏保守 ⇒ **不会漏判**（假阴性风险为 0 方向）；进程内基线（`crates/latteset-core/src/scheduler/actor.rs:269-270` 的 `last_page_hashes`，`[t1] §3.2` 读码）随进程重建，不受影响 ⇒ 这次"首轮失真"恰好出现在**进程重启后的第一次编译**（此时只能靠磁盘缓存）。

### 6.3 与 Quick↔Full 共享基线、以及产品 A 的判据口径（把 `pre` 注释事实接到设计上）

* 缓存只按 **engine** 分档，**没有**按编译强度分档（`runner.rs:199-211` 注释明确"故意让 Quick 与 Full 共享"，否则两者交替会把对方产物当"变了"）。
* 跨档实测（t1 §4 + t4 独立复核）：`full1` vs `full2`、`quick1` vs `quick2`、`quick2` vs `full3-after-quick` **逐字节相同**；`full1` vs `quick1` **只差 1 字节 @偏移 43**（`pre` 注释的分钟位，preLen = 44 ⇒ **该字节落在页切片之外**）⇒ 页级三口径双向 **0/28** 变化 ⇒ **页哈希基线可跨档复用，换口径不影响这一结论**。
* **整篇 XDV 指纹跨分钟不稳（作用域必须写准 —— 任务必写项 8）**：TeX Live 的 `xelatex` 把**本地墙钟到分钟**写进 `pre` 注释（` XeTeX output YYYY.MM.DD:HHMM`，注释长 **29 B**；原始字节样例见 `docs/research/tectonic-test-plan.md` 行 52），**`SOURCE_DATE_EPOCH=0` 管不住它**；而 **Tectonic 的 `pre` 注释是固定串 `tectonic`（8 B），无时钟派生字节（epoch 互换实验逐字节相同）** ⇒ **不得把该现象推广到 Tectonic**（出处同上，行 51/52；本报告独立复现的是 XeLaTeX 侧）。
* **产品 A 的判据必须建在页级哈希（含页数）或「首 BOP→EOF」上，不能建在整篇字节指纹上**：实测「整篇 XDV 逐字节」A 命中只有 **10/42**，其中 2 例（`thesis-last-c7`、`multifile-first-c4`）仅因 `pre` 注释分钟位差 1 B @43 被判不等，**凭空掉 4.76 pp 且不确定**（取决于两次编译是否跨分钟）；而「首 BOP→EOF」= **12/42** 且与「逐页全等」**42/42 同真同假**。现实现用的是页级哈希列表比较（`runner.rs:474` 的 `prev == page_hashes`），**本矩阵证明这是正确选择**（`[t3] §6`、`[q].wholeFile`：`byteEqCases` 10 个、`zeroChangeButByteDiff` 2 个、`changedButByteEqCases` 0 个）。

### 8.4 复现纪律（不遵守就会得到假结论）

1. **每个连续用例前必须还原项目中间产物**：Quick 单趟会**读上一趟写下的 `.aux/.toc`**（"目录/交叉引用落后一趟"是产品既定行为）。实测反面：不还原 `tmp/` 时，本应**零变化**的 `thesis-first-c7`（章首插空行）被判「第 2 页变了」——第 2 页**页长不变、差异只在页内 `[643,644]`**，是上一用例 `c6` 写进 `main.toc` 的新标题被本趟读到（顺序伪影）；还原 `tmp/` 后 raw/V1/V2/渲染 = **0/0/0/0**（`[t2] §4.1`、`[t4] §2.4`）。
2. **`SOURCE_DATE_EPOCH=0` 不等于「整篇 XDV 可复现」**：XeLaTeX 的 `pre` 注释按**本地墙钟到分钟**写（§6.3），42/42 用例的自带基线与夹具基线整文件 SHA 不同，但「首 BOP→EOF」与逐页 raw/V1/V2 **全部相同** ⇒ 任何"XDV 逐字节可复现"的断言必须排除/归一化 `pre` 注释（`[t2] §4.2`）。
3. **转换步必须固定完整输出路径**：`xdvipdfmx` 的产物字节依赖输出路径字符串（同路径两跑全等；换名/换目录不等），但逐页 PNG 哈希相同 ⇒ 本批永远渲染到同一个 `_render/fixed.pdf`（`[t2] §4.3`、`[t1] §2.3`）。
4. **真值只用逐页文本 + 逐页位图，不用 PDF 字节**（§2.2）；dpi 固定 120（变化页集合对 72/120/150 dpi 稳健，但哈希值随 dpi 变，换 dpi 不可直接比较）。
5. **`k` 只是 synctex 代理量**：机制公式里的 `m` 是"字节上最早变长的页"；`k` 与 `m` 在 1/42 例（改章标题）不一致（§1.3）。
6. 采集驱动内含断言：任一用例的自带基线（首 BOP→EOF）或基线渲染真值与夹具基线不一致就**立即抛错停止**（起点不干净不允许继续，`[t2] §9`）。

## §9 未验证与局限

> 说明：以下 1–8 条**原样承自 t3 `quant.md` §10**（局限清单，逐条已由 t4 复核）；9–13 条是 F3/F6/F2 的限定与 t4 §11 的未决项，并入同一清单；第 14 条是本批的非目标声明。

1. **样本量**：2 个夹具 × 3 个位置 × 7 类编辑 = **42 用例**。夹具页数 **28 页**（中文 thesis / ctexbook 类，8 章 include + bibtex）与 **74 页**（中文 multifile，20 章 include）；ΣN = **2142** 页-次。单引擎（XeTeX 3.141592653-2.6-0.999998 / TeX Live 2026）、单机、单 OS（Windows）、固定 `SOURCE_DATE_EPOCH=0`（版本见 `data/_env/env.json`）。
2. **编辑矩阵是合成的单点小编辑**：Δsrc ∈ {−3, +3, 0, +9, +15} 字节，锚点由 pristine 确定性推导（`case-plan.json`）。**未覆盖**：跨页整段插入/删除（>1 页）、连续输入（防抖 500 ms 内的合并抖动）、批量替换、跨文件一次多编辑、宏/表格/浮动体重排、图/表/公式编辑。这几类的 FP 规模会显著大于本矩阵（页体整体平移更大），但**方向与公式同构**（仍由 `N − m − 1` 控制）。
3. **页数上限 74 页**：公式 `FP = N − m − 1` 是线性的，绝对量随 N 放大；**比率** `(N−m−1)/N` 只取决于相对位置（首章：28 页档 82.14%、74 页档 89.19%），换算到 300 页文档时"首章编辑"接近"整篇判变"，但**比率不会比 100% 更差**。
4. **真值口径的局限**：渲染真值 = 120 dpi 逐页位图 SHA-256（+ 页切片字节）。位图是**投影**：对"可见像素相同但 PDF 文字层/元数据/不可见对象不同"的变化不敏感，理论上可能**低估**假阴性；本矩阵无此类编辑。t1 用 `pdftotext` 逐页文本做真值的样本给出相同的变化集合（交叉印证），同样未覆盖该类。⇒ 「假阴性 = 0」是**在这 7 类编辑 × 2 夹具上的 0**，不是全域证明。
5. **`k` 是 synctex 派生量**：1/42 例（`multifile-first-c6`）的 `k` 不在变化集合内；公式中的 `m` 应以"字节上最早变长的页"为准（§1.3）。
6. **每页成本是既有基线 + 推算**（§5.1/§5.5）：不是本轮新实测，且 C 的收益依赖"误判页是否在可视窗口内"；`9.14` 与 `14.57 ms/页` 之间有 **1.6×** 不确定度，全量口径是上界。
7. **编辑类型分布未知**：B/A 命中率 12/42 = 28.57% 由矩阵构成决定（c4/c7 占 12/42），**不能**直接外推为"真实使用中的跳过率"；外推需要先量真实编辑分布（t1/t2/t3 与本任务均未量）。
8. **时段/机器**：2026-09-14 采集；XDV `pre` 注释的墙钟分钟位会造成"整篇字节"口径的抖动（§6.3），任何以整篇逐字节为判据的结论都不可复现（页级与首 BOP→EOF 可复现）。
9. **跨档一致性**只在 thesis 28 页档由 t1 §4 实测过（Full/Quick 页级三口径双向 0/28），t3/t5 未重测；42 用例的主路径是 Quick（`xelatex -no-pdf`），Full 只用于建初态 `aux/toc/bbl`。
10. **页切片之外不可见（F3）**：`raw/V1/V2` 都只比较页切片，`pre`/`post` 段差异三口径全部看不见 ⇒ 本报告「假阴性 = 0」的作用域 = **本矩阵 + 本引擎可达产物 + 页切片之内**。可达反例：`post.mag` 1000→2000 ⇒ 三口径 0 变化而渲染 28/28 页全变（`[t4] §7a`，`review-work/dpi/post-mag.pdf`）。
11. **V1/V2 精确率 100% 是矩阵事实（F6）**：可达反例是「页内不可见 `\special`」（`C_V1 = {1}`、`R = ∅`）⇒ V1 会多报该页（保守方向，不漏判）；矩阵未覆盖该类编辑。
12. **引擎域（F2）**：全部实测只在 **XeTeX（TeX Live 2026）+ xdvipdfmx** 上；「`prev` 必然自洽」一类表述的主语必须收成该引擎。换引擎/转换器需重验的两条：① 两页 `bop` 之间是否会出现长度会变的填充字节（会让 `raw 全等 ⟹ V1 全等` 的反向失效）；② 计数器（`c0..c9`）是否参与渲染（决定 V2 是否安全）。t4 的 `\special` 实验只覆盖 XeTeX 的页外 special 归位行为。
13. **t4 的未决/边界项**：① 只测 XeTeX + xdvipdfmx（同第 12 条）；② 位图真值对"像素不可见差异"不敏感（第 10/11 条已给双向实证）；③ 「删章/页数变化」分支只在 thesis 上跑过一次，未在 multifile 74 页档重复。
