# 实时预览与"正确编译"的成本实测（2026-09-14）

> 目的：为"左边输入、右边 ~200 ms 内看到渲染预览 + 尽量快的正确编译"这个目标，把**成本结构**量出来，
> 再决定「库形态 vs 子进程」「换不换引擎」「草案层放哪里」。
>
> 口径：同批、机器空闲、`SOURCE_DATE_EPOCH=0` 固定、每档预热后取多次；**逐次校验产出**（exit code + PDF/XDV mtime），
> 未通过校验的样本一律作废（本文记录了作废的那一次）。

## 6. 派生结论

1. **固定地板（英文空体、无 PDF 后端）**：XeLaTeX **583 ms**；Tectonic 同口径**且含 PDF** 只要 **283 ms**。
2. **CJK 前导层**：xelatex +207 ms（zh-min − en-empty）、Tectonic +199 ms ⇒ **两边接近**，不是差异来源。
3. **正文成本**：28 页 ≈ 168 ms（**≈6 ms/页**）、74 页 ≈ 385 ms（≈5.2 ms/页）⇒ 页数不是主要矛盾。
4. **PDF 后端才是差异**：Tectonic 进程内 ≈ 882 − 599 = **283 ms**；外部 `xdvipdfmx`（28 页）= **883 ms**（≈**3×**）。
5. ⇒ **击键路径（单趟 + 出 PDF）**：现状 **≈1.96 s** → Tectonic 子进程 **0.88–1.07 s**（≈ −50%）；若只要 XDV（页哈希 A/B/C 路径）则 **0.60 s**。
6. **200 ms 草案层**：数据侧成本 = 解析 44 ms（webview 实测，一次性/每次 reload）+ 逐页文本层 ~1.4 ms（只需可视 2–3 页 ⇒ ~4 ms）+ 折行算术 ~13 µs ⇒ **预算充裕**，真正成本在绘制（DOM/canvas），不在取数。
7. **路线①（引擎自带 PDF）在延迟上严格优于路线②**：② = Tectonic XDV 0.60 s + 外部转换 0.88 s = **1.48 s** > ① 的 0.88–1.07 s ⇒ 与既有 D2 裁决（① 为 P0、接受 B/C 失效）**在延迟维度上一致**。

## 7. 作废样本记录（方法学）

**第一次 E1b 作废**：我把 `TECTONIC_CACHE_DIR` 指到一个**新建空目录**又加了 `-C`（只用缓存），四次探针全部在 **160–208 ms** "成功"返回 —— 破绽正是**四条几乎相同的平坦曲线**（28 页文档不可能 171 ms），真因是**瞬间失败**而我把输出丢进了 `$null`。加上"逐次校验 exit code + 产出 mtime"后立即暴露。
⇒ 纪律：**任何计时必须逐次校验产出**（本项目 §7.7 测量方法学的同一条）。

另：Tectonic 对**空文档**（`zh-pre`：`\begin{document}\end{document}`）`-r 0` 出 PDF 会 **exit=1 且无产出**，而 xelatex 正常 ⇒ 该边界值得记入兼容性清单（未深挖机制）。

## 8. 局限

- 单批测量、单机；机器状态（供电/温度）会影响绝对值（本项目有过一次断电后的测量复盘）。
- 只量了 4 个探针 + 2 个夹具；未覆盖图片/公式密集文档。
- E2 的"本地重排"是**折行算术下界**，不含真实绘制与 DOM 成本。
- Tectonic 地板里"启动 + bundle 缓存 + format 加载"的**内部拆分未测** ⇒ 库形态能再省多少，只有上界估计（≤283 ms）。
- 未测 `.spx`/`--outfmt html` 与 `handle_text_and_glyphs` 的真实数据量与时延（库形态草案层的替代数据源）。
