## 2. 评分模型

四项 1–5 分，**分数越高＝该维度越强/越贵**：

| 维度 | 含义 | 打分依据 |
|---|---|---|
| **W** 痛点权重 | 该痛点在市场中的频率 × 严重度 | 调研的量化信号（issue 数、SE 票数/浏览量、来源数） |
| **D** 差异化 | 相对竞品能否形成壁垒 | 5＝竞品结构性做不到；3＝大家都有但可做得更好；1＝无意义 |
| **C** 实现成本 | 工程投入 | 5＝数月/高风险；4＝数周；3＝1–2 周；2＝几天；1＝小时级 |
| **V** 验证难度 | 能否证明"真的做好了" | 5＝需干净机器/多人/长期；3＝需真机交互且含主观判断；**2＝MCP 驱动可确定性断言**；1＝单测即可 |

**优先级分**：`P = (W + D) / (C + V)`
**分档**：P0 = `P ≥ 1.3 且 W ≥ 4`；P1 = `P ≥ 0.9`；P2 = `P ≥ 0.6`；`P < 0.6` 或定位冲突/已证伪 = 不做。

## 5. 分档详述（未完成项）

### 5.1 ⑲ 模板样本调研（**先做这个**，它决定 ②-2 该不该现在做）

- **问题**：产品默认引擎已是 XeLaTeX，中文模板多数本就能开箱即用；真正会错的是**英文期刊模板走 pdflatex** 的场景。当前"默认 xelatex 覆盖多数"只是 `[推断]`。
- **做什么**：收集 10–20 个真实模板（学校学位论文 + 期刊模板 + 常见会议），统计 `\documentclass` / `ctex` / `fontspec` / `biblatex` / `minted` / `subfiles` 的分布与默认引擎需求。
- **产出**：一张分布表 + 「有多少比例在默认 XeLaTeX 下开箱即用」的数字。
- **DoD**：数字可复现（脚本 + 模板清单），并据此决定 ②-2 的范围（只做 ctex/fontspec 高置信信号？还是不做）。
- **成本**：C=1（半天内）；**不需要改产品代码**。

### 5.2 ②-2 引擎推断

- **做什么**：core 纯函数 `infer_engine(...) -> Option<EngineHint{engine, reason}>`；**只对高置信信号推断**（`ctex`/`xeCJK`/`fontspec`/`unicode-math` → xelatex），无信号则不推断（保持全局默认）。
- **关键设计决策（已在分析中定）**：探测结果**不落盘**（留在 `ProjectState.detected`），UI 可见 + 一键采纳才写项目覆盖；优先级 `用户显式覆盖 > 探测 > 全局默认`。
- **DoD**：3 个真实模板（ctexbook 中文论文、IEEEtran、biblatex 论文）零配置打开即可编译；推断理由在 UI 可见、可覆盖。
- **风险**：**探测错比不探测更糟**（引擎选错的错误不可读）→ 只做高置信信号 + 理由可见 + 逃生门已存在（设置页）。

### 5.3 ④ 错误诊断升级（含 ②-3 缺包诊断）

- **做什么**：在既有 log_parser（解析 + 同源去重 + 点击跳转）上叠加「归类 + 人话解释 + 修复建议」；第一批模式：缺 `.sty`/`.cls`、未定义控制序列、括号未闭合、字体缺失、`Emergency stop`、非 UTF-8 源（**已修的解码问题对应的提示语**）。
- **DoD**：真实错误样本集（≥20 例）中 ≥80% 能给出「原因 + 改哪一行 + 怎么改」；不能解释的降级为原文 + 行号。
- **验证**：样本集快照测试（core）+ MCP 点条目断言编辑器行号。

### 5.4 ③ 性能基准与回归基建

- **做什么**：**脚本生成**基准工程（小/中/大/多文件/重图五档，避免入库大文件）+ 一条命令产出「冷编译 / 增量编译 / PDF 重载（fetch·parse·render）/ 端到端延迟」报告，对照 [design.md](../design.md) §延迟预算。
- **顺带**：把本轮用手做的 MCP 真机验收步骤固化成清单（无需代码），作为回归手段。
- **DoD**：一条命令出报告；超预算标红（CI 或本地检查）。
- **风险**：大文档样本需自己合成（不可分发他人论文）。

### 5.5 ⑤ SyncTeX 可靠性加固

- **做什么**：多文件/`\include` 嵌套、beamer、未加载页、大文档坐标偏移；`synctex(busy)` 竞争重试；失败时降级提示。**并把 ㉒（目录区映射到 `.toc`）一并考虑**——两者同属"点击 PDF 的映射语义"。
- **DoD**：multifile + beamer + 大文档三组样本的正反向成功率与"跳到位"比例记录在案。
- **验证**：MCP 点 PDF → 断言「编辑器文件 + 行号」（本轮已验证该断言可行）。

### 5.6 ⑥ CLI + MCP 接口

- **现状**：计划与清单见 [cli-mcp-plan.md](../cli-mcp-plan.md)（P0/P1 优化点与落地顺序已定）；**ADR-0010 之后 headless 复用更直接**（core + infra 都不依赖 Tauri）。
- **杠杆价值**：既是差异化能力（Agent 可直接驱动「读 → 改 → 编译验证 → 修」），也是其他项的**自动化验证手段**。
- **注意**：`compile_now` 目前是 fire-and-forget，`compile --wait` 需要包装（见 cli-mcp-plan §4 P0-1/2）。
