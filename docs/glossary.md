# Latteset 术语表

本表是 Latteset（本地运行的 TeX 完整 IDE，桌面 GUI，核心设计因素是实时编译）的 **ubiquitous language**：产品、设计与代码里出现的这些词只有一个含义，讨论与文档一律照此用；每条末尾的 `_Avoid_` 是被淘汰的说法。
括号里的 ㉘ 一类是 [roadmap.md](./roadmap.md) 的条目编号（全仓检索键，编号含义以该文为准）。

## Language

**Latteset**:
项目正式名称。**Latte + Typeset**——"一杯拿铁的时间，排版已经跟上"，与实时编译的核心设计因素绑定。配置目录随名：`.latteset/`。
_Avoid_: TeXEditerB、TeX Editor B（更早的占位名）、TeXPresso（**旧名，因与上游 [let-def/texpresso](https://github.com/let-def/texpresso) 撞名而弃用**）

**实时编译 (Real-time compilation)**:
本产品的核心设计因素：文档随用户编辑自动持续编译，无需手动触发构建命令。触发语义见下文两种编译模式。
_Avoid_: 自动编译（含义过宽，且"自动"会与后台任务混淆）、增量编译（只是实现手段之一）

**完整 IDE (Full IDE)**:
产品类别：在本地桌面运行的编辑器，覆盖 编辑 → 编译 → 预览 的完整链路，无服务器组件。
_Avoid_: 写作工具、轻量编辑器

**编译 (Compilation)**:
从 .tex 源文件出发、经 TeX 引擎（及辅助工具如 bibtex）产出 PDF 的过程。结果状态见「Compile status」：未编译、排队中…/排版中…、就绪、失败（失败分内容错误与超时两种，重试语义不同）。
_Avoid_: 构建（与通用编程语境混淆）、渲染（那是预览环节的事）

## Compile modes

**连续编译 (Continuous compilation)**:
编译模式之一：输入停顿即自动触发编译，无需保存。优先实现，与保存触发模式可随时切换。
_Avoid_: 自动编译、实时模式（实时是产品级说法，这里指具体的触发机制）

**保存触发编译 (On-save compilation)**:
编译模式之二：保存文件时触发编译。与连续编译模式可随时切换。**界面文案写「保存时编译」**（双模式并可随时切换）。
_Avoid_: 手动编译（那是第三个概念，指用户点按钮）、保存触发（界面）

**自动保存 (Auto-save)**:
连续编译模式下，编辑器在输入停顿后自动把改动写入磁盘的机制，用户全程无需手动保存。与保存触发编译的区别：前者的保存是编译链路的自动环节，后者的保存是用户显式操作。
_Avoid_: 手动保存（那是另一个概念，指用户按 Ctrl+S）

## Compile status

**未编译 (Not compiled yet)**:
打开项目后还没完成过任何一次编译（首编尚未开始 / 正在进行但未终结）。界面：无项目时**不渲染**状态 chip；有项目且未编译时状态栏显示中性灰「未编译」，问题面板空态显示灰圈「还没有编译」。它由**前端** `hasCompiled` 派生（后端 `CompilePhase` 没有 `idle` 相位，零 DTO 变化）：成功或失败任一终态后置真（此后不再显示「未编译」）；**打开/切换项目时必须重置**，否则会把上一项目的「就绪」或旧错误带过来。
_Avoid_: 空闲、idle、初始态

**就绪 (Ready)**:
当前状态：最近一次编译成功、且没有排队/运行中的编译。**只有编译成功过至少一次才解锁「就绪」**（首次编译前的「未编译」不是就绪）；失败显示「失败· 内容错误 / 失败· 超时」。
_Avoid_: 编译成功（那是事件结果，不是当前状态）、已编译、空闲

**排队中 / 排版中 (Queued / Running)**:
编译进行态的两个词：`排队中…` = 请求已入队、引擎还没开始（合并队列最多一个等待条目）；`排版中…` = 引擎正在跑、屏幕上的 PDF 还是上一版。工具栏「编译」按钮与状态栏 phase 使用**同一份派生文案**（`services/compileStatus.ts`），不得把排队说成排版中。
_Avoid_: 编译中（笼统，分不清排队/排版）、正在编译

## Preview

**内嵌预览 (Embedded preview)**:
应用内 PDF 面板，编译成功后自动刷新并保持滚动位置。v1 必须。
_Avoid_: PDF 查看器（那是外部程序）

**同步提示 (Sync hint)**:
预览工具条上的一句话反馈：反向定位落到**生成产物**（目录/参考文献等，如 `tmp/main.toc`）或项目外文件、
同步数据缺失、正向定位失败时显示，约 5s 自动消失。
**生成产物永远不会被当成源码打开**——能就近回落到真实源码就跳过去（提示"已回落"），回落不到就只提示。
_Avoid_: 报错弹窗（提示不是错误对话框）、通知

**外部查看器 (External viewer)**:
系统默认 PDF 程序作为预览目标，后续版本支持。

**TeX 引擎 (TeX engine)**:
执行编译的底层排版程序。本产品**只有 Tectonic 一个引擎**；xelatex / pdflatex / lualatex 与 latexmk 驱动已从产品中删除（[ADR-0015](./adr/0015-tectonic-only-embedded-engine.md)；②段已把内嵌收成唯一形态，见 [roadmap.md](./roadmap.md)「Tectonic 唯一引擎重构」）。
_Avoid_: 编译器（与通用编程语境混淆）、latexmk（它是驱动，不是引擎）

**内嵌引擎 (Embedded engine)**:
Tectonic 以库的形式编进产品进程（`crates/latteset-tectonic`），是**唯一引擎运行形态**：不启动外部进程、不要求本机安装 TeX Live、不调用外部 biber。阶段②（[ADR-0015](./adr/0015-tectonic-only-embedded-engine.md) 决策 2）已删除子进程路径、`tectonic.lib_form` 设置与 `LATTESET_TECTONIC_LIB` 覆盖开关；**所有构建都需要 vcpkg**。bundle 与缓存目录仍是可配资源（设置里的 `tectonic.bundle` / `cache_dir`）。
_Avoid_: 子进程档 / 库形态 / 库内嵌 / 两形态 / 形态位（**这些说法已随②段删除**；正式叫「内嵌引擎」，没有另一种形态可对照）；"内嵌预览"指预览面板，不是引擎

**宏包集 (Bundle)**:
引擎编译时读取的宏包与字体集合（TeX Live 的子集）。分发方案已在③段按 [ADR-0016](./adr/0016-ship-bundle-offline.md) **候选 A 落地**：安装包**自带内置精简宏包集**（517 文件 / 30.43 MiB zip，覆盖代表性文档集：论文/幻灯片/中文 Fandol 四款/图表/参考文献），**首次编译不需要联网**（完整默认 bundle ≈ 2.88 GB，不随包）。三档来源统一用全名（见下三条）；首次出现可括注「宏包集（bundle）」。
_Avoid_: 宏包缓存（缓存是实现细节）、TeX Live（那是一个发行版，不是本产品的资源形态）、完整宏包集假装是默认、bundle 源、精简集（单独作全名）

**内置精简宏包集 (Shipped bundle)**:
随安装包分发的「代表性文档集」宏包集（`tectonic-bundle.zip`，digest `9e8c63ca…`）——产品**默认 bundle 来源**，支撑**离线开箱**。它**不是完整 TeX Live**：覆盖外的宏包缺失时给可行动诊断，用户在「设置 → 引擎 → 宏包集来源」显式选择另外两档——**在线完整宏包集**（`https://…`，首次按需取包、之后复用缓存）或**本地目录宏包集**（`file:///…`/相对路径，需自带 `SHA256SUM`）。**任何缺包/缺集都不会自动换源**（ADR-0016 决策 2）。
_Avoid_: 自动联网补包、把完整 bundle 2.88 GB 当作随包物、内置（默认）/内置精简集/内置宏包集（非全名）

**在线完整宏包集 (Online full bundle)**:
用户在「设置 → 引擎 → 宏包集来源」**显式选择**的完整宏包集（`https://…` 地址）：首次编译需联网按需取包（一次性成本实测 344 s），之后离线复用缓存；覆盖比内置精简集全。**不会自动切换**——内置集缺失/缺包时只提示用户来显式选择（失败会显式报错）。
_Avoid_: 在线完整 / 在线集 / 完整集 / 在线完整包（作全名）、自动联网补包

**本地目录宏包集 (Local bundle)**:
用户/内网自备的宏包集目录（`file:///…` 或相对路径，设置面板里可填 `E:\bundles\tex` 这类普通路径）——需是 Latteset 可识别的宏包集目录且自带 `SHA256SUM`；用于离线/内网部署或补自备宏包。
_Avoid_: 本地文件夹 / 本地目录 / 本地 bundle / 本地集（作全名）

## Project

**项目 (Project)**:
一个文件夹，含一个根文件和若干子文件。打开文件夹即打开项目。
_Avoid_: 工作区、工程（编程语境词汇）

**根文件 (Root file)**:
编译的出发文件：含 `\documentclass` 的顶层 .tex，`\input`/`\include` 指向的文件视为子文件。自动探测，可手动覆盖。
_Avoid_: 主文件、主 tex（不精确）

**中间文件 (Intermediate files)**:
编译过程的副产品：.aux / .log / .toc / .out 等。统一收纳在项目内 tmp/ 子目录中，不污染源码目录，可进 .gitignore。
_Avoid_: 辅助文件、构建产物（产物指最终 PDF）

**PDF 产物 (PDF artifact)**:
编译的最终结果，位于项目根目录、与根文件同级，便于直接拷贝使用。
_Avoid_: 输出、产物（与中间文件混淆）

## UI

**问题面板 (Problems panel)**:
窗口底部的问题区（默认折叠），标题「问题」，列出错误与警告；条目给「原因 + 建议（→ 怎么办）」，点击跳转到源码行。计数只有一个口径：`services/errorGroups.ts` 的 `groupErrors().total`（同文件 + 同原因算一条，`×N` 是重复次数）；状态栏折叠头显示「N 个问题」，面板标题旁显示同一数字；展示上限 MAX_DISPLAY 只作计算常量，**不进文案**；超出时写「已隐藏 N 条重复问题」并给「显示全部」。空态三态：未编译 → 灰圈「还没有编译」；running → 「排版中…」；完成 → 绿勾「没有发现问题」。
_Avoid_: 报告 / 错误列表 / 诊断面板 / 「已诊断 N」

**行列号 (Line/column)**:
状态栏显示光标位置，沿用编辑器惯例 `Ln 12, Col 5`（T25 判 keep，不换中文以免宽度抖动）；正文叙述可写「第 12 行，第 5 列」。
_Avoid_: 在状态栏写「第 12 行，第 5 列」

## Compile scheduling

**编译队列 (Compile queue)**:
编译调度机制：运行中的编译执行完毕（不中断）；待编译的条目最多保留一个，且总是最新的（合并语义）。最大可见延迟 ≈ 两次完整渲染时间。
_Avoid_: 杀旧启新（已否决：反复中断会让渲染迟迟不落地）

**超时 (Timeout)**:
单次编译超过上限（默认 120s，可配置，上限 1800s）被强制终止的失败。
超时**不自动重试**（同一源码同一上限重跑几乎必然再超时，只是让用户多等一个完整窗口），而是
立刻失败并给出一条**证据化诊断**（首编与否、源文件数、**引擎输出**已排版到第几页 → 判断"慢"还是"疑似卡住"）
与一键「提高到 Ns 并重试」；队列有等待条目时直接执行等待条目。
证据取**已捕获的引擎输出**（捕获的 `.log` + 引擎状态环尾部 + 已上报的最大页）；内嵌形态的日志边写边在内存里，**协作式取消**（没有进程可树杀，引擎在下一个 I/O 回调处中止）——所以"强制终止"在 UI 上的实际延迟必须如实表达。
若证据里已有致命错误（引擎报错后没停），诊断直接报那条错误——那种情况提高超时救不了。
_Avoid_: 卡死（那是现象，超时是机制）

**内容错误 (Content error)**:
源码本身的问题（语法错误等）导致的编译失败。不重试；队列有等待条目则直接执行最新版本，否则展示错误信息。
_Avoid_: 编译报错（笼统，分不清与超时的重试差异）

**手动终止 (Manual abort)**:
用户点击停止：终止运行中的编译（内嵌形态走**协作式取消**：置位后引擎在下一个 I/O 回调处中止，没有进程树可杀），并清空队列中的等待条目。
_Avoid_: 取消（含义过宽）

**延迟预算 (Latency budget)**:
从停止输入到 PDF 刷新：小文档 1s 优秀 / 2s 及格；大文档 3s 优秀 / 5s 及格。**注**（㉘）：编辑期由草稿编译出图，判预算看的是这一趟；紧随其后的空闲收敛不占"编辑→出图"的路径。内嵌形态下"草稿 vs 完整"是**预算判定的结果**（预算内收敛即报完整，见 [dev/modules.md](./dev/modules.md) §2.7）。

**增量编译 (Incremental compilation)**:
只重编受影响部分的策略。**注意**：㉘ 的"草稿 + 收敛"不是增量编译——它不减少单趟工作量，只是把"编辑期那一趟"从 latexmk 的外层机制（perl 启动 + `.fdb_latexmk` 依赖库 + 收敛趟）里解放出来（见 [ADR-0005](./adr/0005-latexmk-first-incremental-next.md)）。此路已否决：latexmk 的"增量"＝对整份文档单遍重排，属引擎上限，见 [roadmap.md](./roadmap.md) §4。

## Compile intensity

**编译强度 (Compile intensity)**:
一次编译执行的"多重"程度，与触发源绑定（roadmap ㉘）：
- **草稿编译 / 单趟 (Draft / Quick)**：编辑触发时使用的一趟——只把改动画出来，不追求目录/交叉引用页码收敛；快，但页码可能落后一趟。内嵌形态下"草稿"是**判定结果**：预算内没收敛才停在草稿态（必要时会跑不止一趟），不是固定单趟。
- **完整编译 / 收敛 (Full / Converged)**：跑到交叉引用稳定并完成 bib 趟的那一次。首次编译、手动「编译」、空闲收敛使用。
_Avoid_: 快速编译/完整编译（"快"是结果不是定义；用草稿/收敛这组词）

**空闲收敛 (Idle convergence)**:
草稿编译成功后、用户停手 2s 内没有新编辑时自动补的那次完整编译——把目录/引用页码追上。
任何编辑或新编译都会取消待收敛（避免完整编译占住调度器、把编辑态的草稿编译堵在队列里）。
_Avoid_: 后台编译、自动重编

**引用待更新 (References pending)**:
草稿编译产出 PDF 时状态栏显示的提示：屏幕上的 PDF 里目录/交叉引用页码可能落后一趟。
只由**下一次成功且为完整编译**清除（失败或运行中都不清——屏幕上的 PDF 没变）。
_Avoid_: 编译中（那是 phase，不是强度提示）

## Documents

**小文档 (Small document)**:
单文件或一次完整编译 ≤ 2s 的文档（典型：期刊论文、笔记）。
_Avoid_: 短文档（与篇幅混淆）

**大文档 (Large document)**:
多文件或一次完整编译 > 5s 的文档（典型：毕业论文、书稿）。
_Avoid_: 长文档（与篇幅混淆）
