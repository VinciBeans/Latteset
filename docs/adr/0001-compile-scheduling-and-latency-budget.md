# 合并队列调度 + 延迟预算

实时编译是产品的核心设计因素，调度语义直接决定"输入到渲染"的体验。我们否决了直觉上更常见的"杀旧启新"，采用**合并队列**：运行中的编译执行完毕、不中断；待编译条目最多保留一个且总是最新；最大可见延迟 ≈ 2× 完整渲染时间。

- **状态**：已接受
- **备选方案**：杀旧启新（否决：反复中断会让渲染迟迟不落地，用户停停打打时延迟反而增加）；无合并的纯排队（否决：延迟累积，旧结果无意义）
- **影响**：调度器成为全项目最需要单测覆盖的核心；失败语义分三路——超时（120s，重试一次）、内容错误（不重试）、手动终止（停运行 + 清队列）
  > ⚠ 已被 roadmap ㉕ 修订（2026-09）：超时**不自动重试**（同一源码同一上限重跑几乎必然再超时），改为立刻失败 + 证据化诊断 + 一键「提高到 Ns 并重试」；上限 600→1800s。见 [design.md §失败语义](../design.md)、[roadmap §1 基线](../research/tex-ide-roadmap-priority.md)。
- **约束**：延迟预算 小文档 1s 优/2s 及格、大文档 3s 优/5s 及格，是增量编译策略的验收标准
  > ⚠ 阈值待重定（见 [roadmap §10-B 第 6 条](../research/tex-ide-roadmap-priority.md)：实测"冷编译 ≤2s 的小文档"在本机几乎不存在，小/大文档分类与 1s/2s、3s/5s 阈值需重新定义）。
