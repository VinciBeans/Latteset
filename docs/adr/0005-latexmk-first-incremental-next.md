# latexmk 起步，增量编译为首要后续任务

编译驱动 v1 用现成的 **latexmk**（自建 watcher 触发，`-outdir=tmp`，不用 `-pvc` 以保留状态控制），不重造引擎驱动；延迟预算（小文档 1s 优/2s 及格、大文档 3s 优/5s 及格）作为优化方向的验收标准；MVP 完成后**增量编译**（只重编受影响部分）是首要任务，性能瓶颈出现时以预算为标尺评估是否自研驱动。

- **状态**：已接受（2026-08 实测补充：见 [design.md](../design.md)「延迟预算实测与结论」——latexmk 增量 = 整份文档重跑一次 xelatex 单遍（xelatex 引擎特性，自研驱动无法突破）；中小文档增量 1.5–2.3s 达标。据此**确认暂不过 latexmk**，自研驱动留作真正大文档超预算时的评估路径。）
  - **2026-09 补充（㉘，不改本决策）**：虽不替换 latexmk，但**编辑期可以绕开它的外层开销**——实测「直调引擎单趟」比完整 latexmk 快 **40.2% 中位**（省的是 perl 启动 + `.fdb_latexmk` 依赖库读写 + 收敛趟，不是少跑 LaTeX）。落地形态：编辑触发 `CompileKind::Quick`（单趟）→ 停手 2s 空闲收敛 `Full`（完整 latexmk，多趟 + bib + 索引），草稿期间 UI 提示「引用待更新」；首编与手动「编译」始终 Full。这与"增量编译"不是同一件事（不减少单趟工作量），故本 ADR 的结论（增量＝整份单遍重排，属引擎上限）依然成立。见 [design.md](../design.md) §延迟预算实测附节。
- **备选方案**：v1 即自研驱动（否决：重造轮子，多趟编译/bibtex/依赖跟踪全是坑；保留优化路径即可）
- **影响**：编译速度优化的讨论有了量化终点，而非无底洞
